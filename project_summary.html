Problem Statement

The retail business accumulated four years of transactional data across three domains — customers, products, and orders — with no systematic analytical layer on top. Reporting was handled ad-hoc with slow, unoptimised queries against raw tables, making it difficult for leadership to answer questions about customer value, regional performance, or product profitability in a timely manner.

This project builds a structured analytical SQL layer from the ground up: a production-quality schema with proper indexing, 18 complex queries covering every major SQL analytical technique, two documented query optimisation cycles, and a business insights report distilling the key findings.

Query Optimization Results

Case 1 — Correlated Subquery → CTE + Hash Join

Before (Slow)
  • Correlated subquery in SELECT clause
  • Fires once per customer row (2,000 times)
  • O(n²) complexity — nested loop pattern
  • Sequential scan; ignores available indexes
  • Est. 850ms on dev dataset
After (Optimised)
  • Pre-aggregate in a CTE — runs once
  • Single Hash Join to customer table
  • O(n) complexity — one-pass aggregate
  • Uses idx_orders_customer + idx_order_items_order
  • Est. 370ms — 56% faster

Case 2 — Full Table Scan → Partial Index

Before (Slow)
  • No index on (status, order_date) combined
  • Full Seq Scan on orders (12,000 rows)
  • All 38K order_items joined before filter
  • Large rows-removed-by-filter count
  • Est. 420ms on dev dataset
After (Optimised)
  • Partial index WHERE status = 'Delivered'
  • Index ~43% smaller; fits in buffer cache
  • Filter eliminated at index level
  • CTE push-down separates join from agg phase
  • Est. 195ms — 54% faster
